📊 EdgeDash
Stop guessing which jobs are actually worth your time.

[Access the Live App Here](https://sree-kirthana-edgedash.streamlit.app/)

EdgeDash is an autonomous job-market intelligence dashboard. It fetches live job listings on a schedule, scores each one deterministically against your own skills and preferences, and surfaces the skill gaps that are actually costing you the most opportunities — all verified before it's trusted, and all visible when it isn't.

---

## 🧠 What it does, in two sentences

EdgeDash runs a daily pipeline — Fetcher → Scorer → GapAnalyzer → Verifier — that pulls job listings, scores them against a fixed set of rules (not an LLM's opinion), and ranks the skills you're missing by real opportunity cost. Every cycle is verified before its data is trusted by the dashboard, and every failure — quota limits, timeouts, bad data — stays visible in an activity log instead of being hidden.

## 🏗 Architecture

```
Trigger (GitHub Actions, daily 06:00 IST)
        │
        ▼
   Orchestrator
        │
   ┌────┼─────────┬─────────────┐
   ▼    ▼         ▼             ▼
Fetcher  Scorer  GapAnalyzer  Verifier
   │       │         │            │
   └───────┴─────────┴────────────┘
                │
                ▼
        Hosted Postgres (Supabase)
                │
                ▼
      Streamlit Dashboard (read-only)
```

- **Fetcher** — pulls raw listings from job board APIs, filters by keyword and city.
- **Scorer** — extracts structured facts from each listing (via LLM) and computes a deterministic 0–100 fit score. No score is ever assigned by an LLM's judgment call — the arithmetic is fixed and auditable.
- **GapAnalyzer** — pure SQL/aggregation, no LLM calls. Ranks missing skills by opportunity cost (how many good-fit listings you're locked out of).
- **Verifier** — runs a set of sanity checks against the cycle's output before marking it "verified." A failing cycle never overwrites the last known-good data.
- **Dashboard** — strictly read-only. It never triggers a cycle; it only displays what the scheduler already verified.

## 🤔 Why these decisions were made

**Storage behind one module.** Every database call goes through `storage.py` — no other file imports `sqlite3` or `psycopg` directly. This meant swapping local SQLite for hosted Postgres at deploy time touched exactly one file. That constraint, written in week one, paid for itself the day of deployment.

**No model-generated SQL.** The "Ask your data" feature answers questions using a fixed set of pre-written, parameterized query tools — never a raw SQL string generated by an LLM. This closes off SQL injection risk and keeps every possible answer traceable to a known, reviewed query.

**The Verifier is not allowed to repair data.** If a cycle's output fails verification, the Verifier does not try to fix it or partially accept it — it fails the cycle outright and the dashboard keeps showing the last cycle that did pass. Silent partial-correctness is worse than an honest "this didn't pass."

**Deterministic scoring, not LLM-judged scoring.** Fit scores come from a fixed weighted formula (skills match, seniority match, location match, recency) — never from asking an LLM "does this look like a good fit?" This makes every score reproducible and explainable, and removes an entire class of prompt-injection risk from listing descriptions.

**Fail loud, never silent.** Failed and degraded cycle runs stay visible in the activity log rather than being swept away — including a live "Show raw error" detail behind a collapsed toggle. An unattended system's most dangerous failure mode is silence, not a crash.

## 🛠 Tech Stack

- **Framework:** Streamlit (dashboard) + Streamlit Community Cloud (hosting)
- **AI/LLM:** Gemini API — used only for structured fact extraction from listing text, never for scoring or SQL generation
- **Database:** Hosted Postgres (Supabase), with a local SQLite fallback for offline development
- **Scheduling:** GitHub Actions — daily cron trigger, isolated from the dashboard process
- **Language:** Python 3.12

## ⚠️ Known Limitations

- **Cross-source duplicates.** The same job re-posted under a new URL is treated as a new listing rather than deduplicated by title/company.
- **Extraction misses.** Some listing descriptions don't parse cleanly into structured facts (formatting, non-English text) and are skipped rather than guessed at.
- **Thin trend data.** Skill-gap trends are only as good as the history accumulated so far — a gap seen in fewer than 3 listings is explicitly flagged as low-confidence rather than ranked with full trust.
- **Free-tier quota.** The Gemini API free tier caps daily requests; the batch size and failure-caching are tuned to stay within it, which limits how many listings get scored per cycle.
